# CEVA BT5.2 Phase 3B-G9E Bridge Egress Protocol v0

## 1. 结论

Egress v0 继续使用当前 EM event window 和 EM[73] event-ready flag。Sidecar 对 Linux 写入的是 Linux HCI driver 可直接上交的 HCI event payload，默认不把 H4 type byte 放进 EM[96] payload。为了兼容 vendor H4TL internal path，v0 额外保留 `event_pkt_type` 元数据，值为 `0x04` 表示 HCI Event。

## 2. 必须回答

1. 是否用 EM[96] event words：是，v0 保留 EM[96..] 为 event payload window。
2. EM[73] event ready flag 是否保留：是，sidecar 写 event 完成后置位，Linux 读完后清零。
3. event 格式是否包含 H4 packet type：EM[96] payload 默认不包含 H4 type；`event_pkt_type` metadata 记录 packet type。如 sidecar 内部走 H4TL，bridge eif 写出时剥离 H4 type。
4. 如何表示 Command Complete：HCI event bytes `0E plen ncmd opcode_l opcode_h status ...`。
5. 如何表示 Command Status / Error：HCI event code `0x0F`，payload `status ncmd opcode_l opcode_h`；bridge error 另写 `event_status`，不能伪装成 vendor success。
6. sidecar 写 event 后如何通知 Linux：写 payload/len/type/seq/status，memory barrier，置 `event_ready=1`，然后触发 Linux 可见 wake path；v0 可由 Linux poll/rx_work 读取，后续再定义 IRQ。
7. Linux 读完后谁清 event ready：Linux 清 `event_ready`，写 `event_consumed_seq`。
8. 怎么证明不是 synthetic：event 必须带 `SIDECAR_HCI_SEND_2_HOST`、`SIDECAR_EGRESS_EVENT_READY`、`LINUX_RX_REAL_EVENT` marker 链，并且 Linux synthetic responder 默认关闭。

## 3. Event memory layout

```text
EM[73]       event_ready
EM[88]       event_len bytes
EM[89]       event_seq
EM[90]       event_pkt_type metadata, 0x04 for HCI Event
EM[91]       event_status
EM[92]       event_consumed_seq
EM[93]       last_event_code / debug
EM[94]       last_event_opcode / debug
EM[96..127]  event payload bytes, HCI event header begins at byte 0
```

EM[80..95] is reserved as egress control/debug area in v0. It must be checked against current driver before coding. EM[96..127] is the event payload area already used by the Phase 2.5 observation path.

## 4. HCI event byte layout

### 4.1 Reset Command Complete

Valid HCI Reset Command Complete payload in EM[96] begins:

```text
0E 04 01 03 0C 00
```

Meaning:

| byte | value | meaning |
|---|---:|---|
| 0 | `0x0E` | Command Complete event code |
| 1 | `0x04` | parameter length |
| 2 | `0x01` | Num_HCI_Command_Packets |
| 3..4 | `0x03 0x0C` | opcode `0x0C03` |
| 5 | `0x00` | status success |

An error response from real vendor runtime is still useful as egress proof if it is real and marker-backed, but it is not `REAL_RESET_PASS` unless status is success.

### 4.2 Read Local Version Command Complete

Valid Read Local Version Information Command Complete payload begins:

```text
0E 0C 01 01 10 00 <hci_ver> <hci_rev_lo> <hci_rev_hi> <lmp_ver> <mfg_lo> <mfg_hi> <subver_lo> <subver_hi>
```

Required checks:

- event code `0x0E`
- parameter length `0x0C`
- opcode little-endian `0x1001`
- status byte `0x00`
- payload length exactly 14 bytes including event code and parameter length

### 4.3 Command Status / Error

Valid Command Status payload begins:

```text
0F 04 <status> 01 <opcode_l> <opcode_h>
```

This proves egress path if generated by vendor runtime. It does not by itself prove Reset success.

## 5. 字段表

| name | address/offset | owner | writer | reader | reset value | valid value | clear rule | debug marker |
|---|---|---|---|---|---:|---|---|---|
| `event_ready` | EM word 73 | shared protocol | sidecar sets, Linux clears | Linux rx path, capture | `0` | `1` means event valid | Linux clears after copying event | `SIDECAR_EGRESS_EVENT_READY`, `LINUX_RX_REAL_EVENT` |
| `event_len` | EM word 88 | sidecar | sidecar | Linux | `0` | `2..128`, v0 initial window validates `<=128` | Linux clears after copy | `SIDECAR_EGRESS_EVENT_READY` |
| `event_seq` | EM word 89 | sidecar | sidecar | Linux | `0` | monotonically increasing nonzero value | overwritten per event | `LINUX_RX_REAL_EVENT` records seq |
| `event_pkt_type` | EM word 90 | sidecar | sidecar | Linux | `0` | `0x04` for HCI event, future `0x02` ACL | Linux clears after copy | capture field |
| `event_status` | EM word 91 | sidecar | sidecar | Linux/capture | `0` | `EVENT_VALID`, `EVENT_ERROR` | overwritten per event | capture field |
| `event_consumed_seq` | EM word 92 | Linux | Linux | sidecar/capture | `0` | last consumed seq | overwritten per event | `LINUX_RX_REAL_EVENT` |
| `last_event_code` | EM word 93 low 8 bits | sidecar debug | sidecar | capture | `0` | HCI event code | overwritten per event | `SIDECAR_HCI_SEND_2_HOST` |
| `last_event_opcode` | EM word 94 low 16 bits | sidecar debug | sidecar | capture | `0` | command opcode in CC/CS | overwritten per event | `REAL_RESET_PASS` / `REAL_RLV_PASS` |
| `event_payload` | EM word 96..127 | sidecar | sidecar | Linux | zero | HCI event bytes without H4 type | Linux may zero after copy in debug builds | `LINUX_RX_REAL_EVENT` |

## 6. Sidecar event write sequence

```text
wait event_ready == 0
serialize vendor event to sidecar private buffer
if buffer starts with H4 type 0x04:
  strip first byte for EM[96] payload
  write event_pkt_type = 0x04
else:
  set event_pkt_type based on vendor message type
write event_payload to EM[96..]
write event_len
write event_seq
write event_status = EVENT_VALID
write last_event_code / last_event_opcode
memory barrier
write event_ready = 1
write SIDECAR_EGRESS_EVENT_READY
notify Linux rx path or wait for poll
```

## 7. Linux event read sequence

```text
if event_ready != 1:
  return
read event_len / event_pkt_type / event_seq
validate event_len and packet type
copy EM[96..] into skb data
set skb packet type from event_pkt_type
call hci_recv_frame or current driver rx boundary
write event_consumed_seq = event_seq
clear event_ready
write LINUX_RX_REAL_EVENT marker
if Reset CC success:
  write REAL_RESET_PASS
if RLV CC success:
  write REAL_RLV_PASS
```

## 8. IRQ / doorbell rule

v0 does not require RTL change for a new sidecar-to-Linux interrupt. The first implementation may use existing driver polling/rx_work observation if available. If a Linux-visible IRQ already exists in the current driver path, egress can use that wake mechanism after it is proven safe.

The protocol rule is independent of wake transport: event is valid only after `event_ready=1`; Linux must not consume partial payload.

## 9. 证明不是 synthetic 的规则

一个 event 只有同时满足以下条件，才能计入 real path：

- Sidecar marker `SIDECAR_HCI_SEND_2_HOST` 已写。
- Sidecar marker `SIDECAR_EGRESS_EVENT_READY` 已写。
- EM[96] payload 与 marker opcode/seq 一致。
- Linux marker `LINUX_RX_REAL_EVENT` 已写。
- Linux synthetic responder 默认关闭，或 capture 明确记录未使用 synthetic branch。
- 对 Reset/RLV pass，HCI bytes 符合本文件第 4 节。

## 10. PASS / FAIL / STOP

PASS 条件：

- Vendor egress path 触发 `hci_send_2_host()` 或等价 sidecar egress seam。
- EM[96] 中出现真实 HCI event payload。
- Linux rx path 读取并上交 event。
- Reset CC 或 RLV CC 的 opcode/status 校验通过。

FAIL 条件：

- sidecar 消费命令但没有写 event。
- event_ready 置位但 payload 不符合 HCI event 格式。
- Linux 收到的 event 来自 synthetic responder。

STOP 条件：

- egress 必须重构 Linux HCI core 才能接入。
- 需要 RTL 改动才能做第一版 Reset/RLV egress proof。
- Vendor event serialization 只能通过未获批 vendor binary/source 完成。
