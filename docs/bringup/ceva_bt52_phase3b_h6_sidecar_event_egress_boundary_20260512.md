# CEVA BT5.2 Phase 3B-H6 Sidecar Event Egress Boundary

## 1. Goal

H6 adds a gated sidecar helper that can publish a future vendor-produced HCI event to the existing Linux host shim EM event mailbox.

This phase does not call the helper from the sidecar main loop, does not synthesize Command Complete, does not run CEVA vendor runtime, and does not claim Linux RX real event PASS.

## 3. Event Format

Linux reads event packets from `EM[96..111]` and expects:

```text
byte 0: HCI packet type = 0x04
byte 1: event code
byte 2: parameter length
byte 3..: event parameters
```

H6 helper behavior:

1. Validate event view pointer, payload pointer, payload length, and payload capacity.
2. Pack the HCI event packet into a zeroed 16-word EM event buffer.
3. Write all 16 event words to `EM[96..111]`.
4. Write event markers.
5. Set `EM[73]` to `0x5A5A5A5A`.

## 4. Gate

`ceva_bt52_sidecar_publish_vendor_event()` is an egress boundary, not a response policy. It must only be called when a future approved vendor adapter returns a real event.

Forbidden in H6:

- Calling this helper from the idle loop.
- Fabricating Reset Command Complete.
- Treating helper build success as real controller success.

## 5. Validation

Validation command:

```bash
bash scripts/build_ceva_sidecar.sh
```

Expected result:

- Build succeeds.
- The map contains `ceva_bt52_sidecar_publish_vendor_event`.
- Generated `.elf`, `.bin`, `.map`, and `.dump` artifacts are cleaned before commit.

## 6. PASS / PARTIAL / BLOCKED

PASS:

- Event egress helper builds into the sidecar image.
- Helper writes the Linux-compatible EM event packet format.
- No synthetic event is generated by the current main loop.

PARTIAL:

- Event egress is not hardware-validated in this commit.
- No Linux RX marker is claimed.
